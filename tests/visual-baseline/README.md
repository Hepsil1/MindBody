# Cross-device visual baseline

Screenshots of saleid.icu across the device matrix the app actually
ships to. Generated by `npm run visual-snapshot`.

Devices (4):

- **iphone-14** — Playwright WebKit, 390×664 DPR 3 (most common 2023-2024)
- **iphone-se** — Playwright WebKit, 320×568 DPR 2 (narrowest viable iPhone)
- **pixel-7** — Playwright Chromium, 412×839 DPR 2.625 (Android baseline)
- **desktop** — Playwright Chromium, 1280×720 (desktop sanity)

Pages (5): home, shop-yoga, auth, pdp, checkout.

Why WebKit specifically: Playwright's webkit engine is the same WebKit
Safari uses on iPhone — same default CSS behaviours. This catches bugs
that Chromium-with-iOS-user-agent emulation misses (the cleanest example
in our history: `.header__burger span` empty `<span>` rendered 0×0 on
real Safari WebKit but 44×2 in Chromium emulation — three burger lines
were invisible on real iPhone Safari for a release).

Screenshots are `.gitignore`d by default — they're a local-run artifact.
If you want to track a frozen baseline (e.g. for visual regression), edit
`.gitignore` here to whitelist a snapshot.

## Commands

```bash
npm run visual-snapshot           # prod (saleid.icu)
npm run visual-snapshot:local     # dev (localhost:3001 — autostarts via Playwright)
node scripts/visual-snapshot.mjs --device=iphone-14   # single device
```

After re-running, view individual screenshots in your editor or via
File Explorer at `tests/visual-baseline/<device>/<page>.png`.
